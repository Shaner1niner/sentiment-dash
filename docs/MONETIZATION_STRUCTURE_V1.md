# SETA Monetization Structure v1

This document outlines likely monetization paths for SETA. It is a product strategy guide, not a pricing commitment.

## Monetization thesis

SETA should monetize interpretation, workflow, and trust calibration, not raw charts.

Many users can already access price charts and indicators. SETA's value is the structured behavioral read:

- what the setup appears to be
- what confirms or weakens it
- whether attention is meaningful
- whether participation appears broad or concentrated
- what deserves follow-up research
- how to communicate the read safely

## What should stay free

The public product should remain useful enough to prove the category.

Potential public/free features:

- public dashboard
- selected asset universe
- limited Market Tape
- basic Briefing Mode
- public context cards
- educational methodology
- delayed or limited refresh detail if needed later

The public product should be strong enough to teach the SETA concept, but not so complete that it removes the need for member workflow depth.

## Paid member tier

The member tier should focus on broader research workflow.

Potential member features:

- full eligible asset universe
- richer Market Tape
- advanced chart controls
- member Briefing Mode
- source breadth and trust detail
- historical briefing context
- expanded watch/event timelines
- saved views later
- alert preferences later

Member value proposition:

> Spend less time hunting for behavioral context and more time evaluating the best candidates.

## Pro or creator tier

The pro tier should serve users who need to communicate SETA reads.

Potential pro features:

- briefing export
- report snapshots
- newsletter-ready summaries
- watchlist packets
- saved commentary templates
- deeper history
- priority refresh or custom coverage later

This tier should still avoid investment-advice claims. It should help users produce research, education, and commentary.

## Enterprise or research tier

The enterprise tier should be considered only after the core product has traction.

Potential enterprise features:

- API access
- custom universe coverage
- team workspaces
- compliance/audit metadata
- briefing archive
- data lineage
- custom dashboards
- white-label research support

Enterprise language should emphasize workflow, research operations, and behavioral intelligence.

## Role of source breadth in value

Source breadth can be a meaningful paid-product differentiator because it helps users evaluate trust.

Possible packaging:

- public: simple breadth/trust label
- member: channel-level breadth detail and caveats
- pro: exportable trust explanation
- enterprise: auditable source-breadth metadata and lineage

Breadth should not be sold as proof that a move is organic. It should be presented as a confidence qualifier.

## Pricing posture

Do not hardcode final prices yet.

Before pricing, validate:

- who uses SETA weekly
- what they use it for
- whether they value the briefing layer more than chart controls
- whether breadth/trust detail changes decisions or communication
- whether users want alerts, saved views, exports, or API access first

Initial pricing can be simple once member value is clearer:

- Free/Public
- Member Research
- Pro/Creator
- Enterprise/Custom

## Guardrails

Do not monetize by implying:

- guaranteed results
- buy/sell recommendations
- personalized investment advice
- proprietary predictions
- certainty from sentiment or breadth

Preferred positioning:

- behavioral market intelligence
- research workflow
- evidence organization
- trust calibration
- educational context
- explainable briefings

## Near-term go-to-market

Recommended near-term path:

1. keep the public dashboard polished and live
2. use founder-led demos for feedback
3. collect a waitlist or early member cohort
4. validate Briefing Mode as the core paid surface
5. add AI-assisted briefings when the input/output schema is trusted
6. add billing only after the tier distinction is obvious

## Success metrics

Useful early indicators:

- repeat dashboard usage
- users asking for broader asset coverage
- users asking to save or export briefings
- users referencing briefing language in their own workflow
- demand for alert/event follow-up
- users asking for historical context
- users understanding breadth as a trust qualifier
